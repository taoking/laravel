# Null Object 空对象模式

## 1. 一句话定义

用一个空对象替代 null，减少空值判断。

## 2. 解决什么问题

调用方到处判断 null 会让核心流程变长，也容易漏掉空值分支。

## 3. 使用场景

用户没有默认地址时返回空地址对象。

- 业务背景：用户没有默认地址时返回空地址对象。
- 普通写法会让变化点和主流程混在一起。
- 使用该模式后，应把变化点、协作对象或流程步骤拆到独立类中。

## 4. 常见使用地方

- 用户资料
- 配置读取
- 权限对象
- 购物车
- 默认值处理
- 避免 null 判断

## 5. 不使用模式可能的问题

- 业务代码容易堆积条件分支或重复流程。
- 新增变化点时修改范围扩大，回归风险升高。
- 单元测试只能覆盖大块流程，难以隔离具体规则。

## 6. 适合使用的情况

- 变化点已经明确，并且预计会继续扩展。
- 同类实现至少有两个，且调用方希望依赖稳定接口。
- 拆分后可以让业务职责、测试目标和扩展边界更清楚。

## 7. 不适合使用的情况

- 当前只有一个简单实现，短期没有扩展需求。
- 引入额外类后可读性反而下降。
- 只是为了套用模式而拆分，没有真实复杂度需要管理。

## 8. Laravel 中的关联点

可用于默认配置、匿名用户、空权限等场景，但不要掩盖本应显式失败的问题。

## 9. 本练习场景

本练习使用“用户没有默认地址时返回空地址对象。”作为业务背景。请只在本目录中完成自己的实现，不要把练习代码散落到已有业务模块。

## 10. 练习目标

- 定义真实对象和空对象统一接口
- 用空对象替代 null
- 减少调用方 if 判断
- 理解不要滥用空对象隐藏错误

## 11. 练习内容

**具体功能：用户默认地址空对象**

你正在实现结算页地址展示，用户可能没有默认地址，但页面仍需要稳定返回收货人、电话和地址摘要。

具体要求：

- 定义地址契约，让真实地址和空地址对象拥有一致方法。
- 没有默认地址时返回空地址对象，而不是返回 null。
- 在 Exercise.php::run() 中演示有地址用户和无地址用户的结算摘要。
- 补充测试验证调用方不需要写多处 null 判断，同时不会隐藏必须报错的场景。

## 12. 建议创建的类

- AddressInterface.php
- UserAddress.php
- NullAddress.php

## 13. 测试建议

- 覆盖正常路径和至少一个边界场景。
- 验证调用方只依赖稳定入口，而不是依赖具体实现细节。
- 测试文件先使用 `markTestIncomplete()` 占位，完成练习后再替换为真实断言。

## 14. 面试表达

空对象模式的重点不是类数量，而是把“会变化的部分”和“稳定调用方”分开。说明时可以先讲业务场景，再讲普通写法的问题，最后说明该模式如何降低修改范围。

在 Laravel 项目中，应优先利用服务容器、事件、队列、Pipeline、FormRequest 等框架机制。只有当这些机制背后的设计边界需要被明确表达时，再引入单独的模式类。
