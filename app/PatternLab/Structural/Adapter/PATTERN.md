# Adapter 适配器模式

## 1. 一句话定义

把不兼容的接口转换成客户端期望的接口。

## 2. 解决什么问题

第三方 SDK 方法名、参数和返回值不一致时，业务层直接调用会被外部接口污染。

## 3. 使用场景

统一不同第三方短信平台接口。

- 业务背景：统一不同第三方短信平台接口。
- 普通写法会让变化点和主流程混在一起。
- 使用该模式后，应把变化点、协作对象或流程步骤拆到独立类中。

## 4. 常见使用地方

- 第三方 SDK 接入
- 支付平台接入
- 短信平台接入
- 地图服务接入
- 文件存储服务接入
- 老系统接口兼容

## 5. 不使用模式可能的问题

- 业务代码容易堆积条件分支或重复流程。
- 新增变化点时修改范围扩大，回归风险升高。
- 单元测试只能覆盖大块流程，难以隔离具体规则。

## 6. 适合使用的情况

- 变化点已经明确，并且预计会继续扩展。
- 同类实现至少有两个，且调用方希望依赖稳定接口。
- 拆分后可以让业务职责、测试目标和扩展边界更清楚。

## 7. 不适合使用的情况

- 当前只有一个简单实现，短期没有扩展需求。
- 引入额外类后可读性反而下降。
- 只是为了套用模式而拆分，没有真实复杂度需要管理。

## 8. Laravel 中的关联点

适合放在 Infrastructure 或 Support 层，并通过容器把统一接口绑定到具体适配器。

## 9. 本练习场景

本练习使用“统一不同第三方短信平台接口。”作为业务背景。请只在本目录中完成自己的实现，不要把练习代码散落到已有业务模块。

## 10. 练习目标

- 定义统一短信发送接口
- 为不同平台创建适配器
- 屏蔽不同 SDK 方法差异
- 让业务层只依赖统一接口

## 11. 练习内容

**具体功能：统一短信平台发送接口**

你正在实现短信发送功能，阿里云、腾讯云和华为云 SDK 的方法名、参数和返回结构都不一致。

具体要求：

- 定义统一短信发送接口，输入手机号、模板编号和模板变量。
- 为至少两个模拟短信平台创建适配器，把不同 SDK 调用转换成统一结果。
- 在 Exercise.php::run() 中演示业务层只依赖统一接口发送验证码短信。
- 补充测试验证不同平台返回结果被规范化成同一种结构。

## 12. 建议创建的类

- SmsSenderInterface.php
- AliyunSmsAdapter.php
- TencentSmsAdapter.php
- HuaweiSmsAdapter.php

## 13. 测试建议

- 覆盖正常路径和至少一个边界场景。
- 验证调用方只依赖稳定入口，而不是依赖具体实现细节。
- 测试文件先使用 `markTestIncomplete()` 占位，完成练习后再替换为真实断言。

## 14. 面试表达

适配器模式的重点不是类数量，而是把“会变化的部分”和“稳定调用方”分开。说明时可以先讲业务场景，再讲普通写法的问题，最后说明该模式如何降低修改范围。

在 Laravel 项目中，应优先利用服务容器、事件、队列、Pipeline、FormRequest 等框架机制。只有当这些机制背后的设计边界需要被明确表达时，再引入单独的模式类。
